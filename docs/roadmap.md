# 路线图

> 原则：**先把"别人能自己装好"这件事做出来，再谈功能。**
> 现在的客户端功能已经够用（悬浮窗、实时转写、发送、回复显示）；缺的全是"没有作者在旁边也能跑起来"的部分。

---

## 现在（v0.1 · 已在日常使用）

- 安卓悬浮条：可拖动、可收起成一粒、位置记忆
- 说话时边转写边出字，可中途停下修改再继续
- 发送按钮在输入框右上角，有字才出现
- 回复在悬浮条内显示，可滚动
- 后端口令校验、单会话
- 小米桌面组件可添加（需手动放行 MIUIOP 10017）

## 下一步（v0.2 · 开源封装的必修项）

已完成：首次启动引导页（`ui/setup/SetupActivity.kt`）、GitHub Actions 自动出包（`.github/workflows/android.yml`）。

剩余按优先级：

1. ~~**首次启动引导页**~~ ✅
   填地址 → 测连通 → 一键申请悬浮窗/麦克风 → 引导关电池优化。
   现在这些都靠 adb 手动做，陌生人装完会直接懵。

2. **参考后端 `server/`**
   一个不超过 300 行的服务，实现 3 个接口，带 3 个 adapter（OpenClaw / OpenAI 兼容 / webhook）。
   目的：证明协议可行，且给人抄。

3. **错误可自诊断**
   "连不上"必须区分：地址错 / 口令错 / 服务没起 / 网络不通 / 权限缺失。
   现在只有一个状态文字，对陌生用户不够。

4. **`docs/faq-xiaomi.md` 的内容进 App**
   装机后第一次添加组件失败，App 里直接给解法，而不是让用户去翻文档。

5. ~~**GitHub Actions 自动出包**~~ ✅
   打 tag → 自动编译 → 挂 Release。别人用 Obtainium 订阅后能自动更新。

## 之后（v0.3+）

- **多会话隔离**：现在只有一个会话通道，多人用会串台。这是搬到任何"给别人用"的场景前必须解决的
- **流式回复（SSE）**：现在是一次性返回。真流式要改协议，不急着做
- **可配置 ASR**：本地 whisper.cpp / 云端 API / 自建，三选一
- **iOS 探索**：悬浮窗不可行。唯一可行方向是输入法或锁屏小组件，属于另一个产品
- **文档国际化**：中文为主 + 英文全量（`README.en.md` 已有，`docs/en/` 待补）。全球用户优先看 Tailscale 那档

## 不做

- **不碰别人的 App**：不做无障碍自动填入、不抓微信/豆包的内容。既违反平台规则，也违背这个项目的定位
- **不做中心服务器**：不提供托管服务。你的话只经过你自己的机器
- **不做通用助手**：不自带模型、不做提示词市场。它只是输入层
