# 第二档 · IPv6 + DDNS 直连（不花钱，速度最好）

> 最适合：想在外面也能用，但不想买服务器、不想买域名。
> 优点：不经过任何第三方中转、延迟最低、不受运营商的 UDP 限制影响（这也是 Tailscale 等组网工具在国内最常见的问题）。
> 缺点：需要一个有 IPv6 的网络；公司/公共 WiFi 往往没有 IPv6。

---

## 前提确认：你真的有 IPv6 吗

**电脑侧（macOS / Linux）**

```bash
# 有全局 IPv6 地址就说明家宽拿到 IPv6 了（以 2xxx: 开头，不是 fe80: 开头）
ifconfig | grep "inet6 2"
```

**手机侧**：手机浏览器打开 <https://test-ipv6.com>，看有没有拿到 IPv6 地址。

两边都有，才走得通这一档。只有一边有，看下面「常见不通的原因」第 3 条。

## 必须解决的三个问题

1. **运营商会不会封 IPv6 入站** —— 国内家宽 IPv6 一般允许入站，但路由器默认防火墙会挡
2. **IPv6 前缀会变** —— 家宽前缀通常是动态的，重启光猫就可能变 → 需要 DDNS
3. **地址太长记不住** —— `2408:8207:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx`，必须用域名或二维码

---

## 第 1 步：路由器放行入站

进路由器后台，找「IPv6 防火墙 / IPv6 安全」：

- 关闭「IPv6 防火墙」的全部拦截，或
- 加一条入站规则：允许 **TCP 到本机 8899 端口**

⚠️ **只放行这一个端口，不要把电脑整个暴露在 IPv6 上。** 家宽的 IPv6 是公网地址，全放行等于把机器挂到互联网上。

## 第 2 步：让服务监听所有地址

```bash
python3 server/main.py --host 0.0.0.0 --port 8899
```

## 第 3 步：先在局域网外验证一次

手机**关掉 WiFi，用流量**，浏览器打开：

```
http://[你家宽的IPv6地址]:8899/api/health
```

> 注意 IPv6 地址在 URL 里必须用方括号包起来。

能看到 JSON = 通了。打不开就回到「常见不通的原因」。

## 第 4 步：配 DDNS（把变动的地址绑成固定域名）

选一家支持 AAAA 记录的 DDNS：

| 服务 | 特点 |
|---|---|
| DNSPod（腾讯） | 国内解析快，API 好用，域名要备案才解析到境内服务器，但**这里解析的是你家宽带，不涉及备案** |
| Cloudflare | 免费、API 简单，国内解析速度一般 |
| DuckDNS | 免费、注册即用，最省事，但域名是它给的二级域 |

配置逻辑就一句：**定时查本机 IPv6，和 DNS 里记录的值不一样就调 API 更新。**

参考 crontab（每 5 分钟一次）：

```cron
*/5 * * * * /path/to/ddns-update.sh >/dev/null 2>&1
```

脚本骨架：

```bash
#!/usr/bin/env bash
set -euo pipefail

IFACE=en0
RECORD="home.example.com"
TOKEN="你的 DNSPOD/Cloudflare token"

IP6=$(ifconfig "$IFACE" | awk '/inet6 2/ {print $2; exit}')
[ -n "$IP6" ] || { echo "no ipv6"; exit 1; }

# 用你选的 DNS 服务商 API 更新 AAAA 记录（各家不同，照官方文档写）
# 关键：先查现有值，相同就不调 API，避免触发限流
```

> 各家 API 的具体写法差异很大，**这里不写死某一家**。选定后照官方文档填 5 行即可。

## 第 5 步：手机里填地址

```
http://home.example.com:8899
```

DDNS 生效后，家里 IP 变了也不用再改手机。

## 常见不通的原因（按概率排序）

1. **路由器 IPv6 防火墙没放行** —— 最常见。临时全关一次验证，通了再改成只放行单端口
2. **服务只监听了 `127.0.0.1`** —— 改成 `0.0.0.0`
3. **手机没有 IPv6** —— 部分运营商流量、部分公共 WiFi 只给 IPv4。此时**这一档走不通**，只能用 [frp](setup-frp.md)（服务器同时有 IPv4 和 IPv6，任何网络都能连）
4. **运营商封了入站** —— 少数地区对家宽 IPv6 入站有限制。判断方法：同一网络下另一台设备用 IPv6 连本机，通说明是手机侧问题，不通就是运营商
5. **公司/学校网络屏蔽 IPv6 出站** —— 换网络验证

---

## 这一档为什么比 Tailscale 更适合国内

- Tailscale 的登录入口和默认中转都在境外，国内经常卡在登录、或被迫走海外中转（延迟 200ms+）
- 家宽 IPv6 直连是**纯 P2P、零中转**，延迟就是物理距离

代价是：没有 IPv6 的网络用不了。所以文档给三档，让用户按场景选，而不是替所有人做一个统一但处处受限的方案。

---

## 验收标准

- 手机关 WiFi 用流量，浏览器能打开 `http://<域名>:8899/api/health`
- 重启光猫后（IPv6 变了），等 5 分钟，手机仍能打开（说明 DDNS 生效）
- 面板「测试连接」通过
